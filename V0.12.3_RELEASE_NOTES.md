# FLIM Studio 0.12.3

## Settings presets (`.ini`) and pre-analysis thresholding

Two usability requests:

### Settings presets

Every sidebar control that feeds into an analysis run can now be saved to
and loaded from a plain `.ini` file — a new **SETTINGS PRESET** section at
the very top of the sidebar (**Load…**, **Save as…**, **Save as default**,
**Reset**). Saving as default writes `default.ini` next to the
application (the project root from source, or next to
`FLIM Studio.exe` in a packaged build), which is then loaded automatically
on every startup — no more re-entering the same timing/threshold/fit
settings each session, and a saved `.ini` is a simple way to hand a whole
acquisition setup to a colleague.

- [`flim_app/settings_ini.py`](flim_app/settings_ini.py) (new) —
  `save_settings_ini`/`load_settings_ini`, a generic, type-driven
  round-trip over every `AnalysisSettings` field via `configparser`
  (`interpolation=None`, since a couple of those fields are free-text file
  paths that could legitimately contain a `%`).
- `flim_app/_paths.py`: new `main_folder()` — distinct from the existing
  `app_root()` (FLIM Studio's own internal resource folder): this is
  "next to the exe" / "the project root", where a user would actually look
  for `default.ini`.
- `flim_app/gui.py`: new `_apply_settings_to_ui()`, the inverse of the
  existing `_settings()` -- pushes a loaded `AnalysisSettings` back onto
  every sidebar control. Best-effort: an unrecognised value for a
  combo-backed field (a hand-edited file, or one from a newer version with
  a choice this one predates) is skipped with a warning rather than
  aborting the whole load. Reuses `_set_row_map_controls` for the detector-
  row map fields and (deliberately not `_activate_trained_model`, to avoid
  it silently overriding the method/fit fields the settings file itself
  specifies) a plain `load_global_model` for the global-model path, for
  its status text only.
- `load_demo()`/`load_path()` skip their own hardcoded demo-specific
  threshold/background overrides when a `default.ini` was loaded at
  startup, so a user's own defaults stay authoritative through the demo
  dataset's auto-load instead of being partly clobbered a moment later.

A settings file only covers *choices* (method, timing, thresholds,
spatial binning, native fit conditions, display ranges, IRF source, …) —
not anything about a specific loaded file (sample/IRF/background paths,
the queue), which aren't "initial values for a choice" so much as
"whatever's open right now".

### Pre-analysis thresholding

Intensity thresholding was previously only available *after* running a
full analysis (the `Intensity with threshold` map mode did nothing until
`self.result` existed). It's now usable as soon as a dataset loads:
switching the Overview tab's second map to `Intensity` or `Intensity with
threshold` previews raw photon counts -- summed over time and spatially
binned exactly as the current **Spatial bin radius** setting -- so a
threshold can be picked (and checked against the current binning) before
spending time on a full run. Changing the spatial bin radius live-updates
this preview.

- `flim_app/gui.py`: `_show_raw_intensity()` now computes
  `self._raw_binned_intensity` via `processing.rolling_spatial_bin` (summed
  over time first, then binned on the 2-D image -- mathematically
  identical to binning first, and far cheaper to rerun on every radius
  change) instead of showing unbinned raw counts; new
  `_refresh_secondary_map_pre_analysis()` renders the Intensity /
  Intensity-with-threshold modes from it (Lifetime/Composite/Chi-square
  still need a real fit and keep showing the "Run analysis" placeholder);
  a new `bin_var` trace (`_on_spatial_bin_setting_changed`) recomputes the
  preview live pre-analysis only -- once a real result exists, changing
  the radius affects only the *next* run, same as every other setting.
  `_live_threshold_entry_changed`'s guard now checks for a loaded dataset
  rather than a finished analysis, so the threshold entry/slider work in
  both states.

The preview is still only an approximation of the real post-fit map:
background subtraction, the timing offset, and row/column interpolation
aren't applied until a real analysis run -- which is what actually
determines which pixels get fitted.

### Status

Implemented and reviewed via careful manual code tracing (no Python
interpreter available in this environment -- see `BUILDING.md`'s existing
caveat). Please exercise both: load a dataset and switch to `Intensity
with threshold` before running analysis, and confirm changing the spatial
bin radius updates it live; and try Save as default / restart / Load…
with a settings file to confirm the round trip behaves as expected.
