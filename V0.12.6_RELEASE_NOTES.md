# FLIM Studio 0.12.6

## Multi-select "Add image(s)…" in the Training dialog

Once a **Shared IRF** (and optionally **Shared background**) is set at
the top of the Training dialog, **Add image(s)…** now accepts multiple
decay files in one file-picker selection (ctrl/shift-click) instead of
one file per click — every selected file is added straight in using the
shared reference data, with no further prompts. Without a shared
IRF/background, each selected file still gets its own interactive
IRF/background prompt (there's no other sensible way to pair per-image
reference data), same as adding one at a time always did — multi-select
there just saves reopening the same file picker from the same folder
repeatedly.

Drag-and-drop was the other option raised for this; went with multi-select
instead since it reaches the same practical goal ("load several images at
once") using the file dialog's existing, already-used-elsewhere-in-this-app
`askopenfilenames` (no new dependency — this app deliberately keeps its
`requirements.txt` to just numpy + Pillow, and drag-and-drop in Tkinter
needs a third-party library like `tkinterdnd2`).

### What's new

- `flim_app/training_gui.py`: `_add_image()` now calls
  `filedialog.askopenfilenames(...)` instead of `askopenfilename(...)`,
  looping the existing per-image logic (now `_add_one_training_image()`)
  over every selected path. Failures/skips across a multi-file batch are
  collected and shown as one combined summary dialog rather than
  interrupting with a message per file; a single-file add's failure still
  shows exactly the same one-line error dialog as before. Button
  relabelled "Add image(s)…"; the dialog's intro text explains the
  behaviour.
