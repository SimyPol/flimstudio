# FLIM Studio 0.11.2

## Browse queue results without re-running

New **Process queue…** button next to the file queue. Unlike the existing
"Process & export queue" (which writes every result straight to disk and
keeps nothing in memory), this runs analysis across the whole queue with
the current settings — including Application mode, so this is how you
apply a trained global model to a folder of images — and keeps up to a
capped number of results in memory. Queue entries that are cached show a
"●" marker; clicking one shows that result instantly, with no re-run.

- **"Keep in memory"** field next to the button sets the cap (default 8).
  Capped by *count*, not raw memory size, since that varies wildly with
  image dimensions and time-bin count — pick a number that's comfortable
  for your image sizes.
- Eviction is LRU: when the cap is exceeded, the **least-recently-viewed**
  cached result is dropped first, not strictly the oldest-processed one —
  so clicking through to revisit an older result protects it from being
  evicted next.
- Loading a new queue (Open files / Open a folder) clears the cache, since
  it's a different set of images.

## Verification

- New `tests/gui_smoke_v12.py`: caches three real analysis results with a
  cap of two, confirms the oldest is evicted and the queue list markers
  update correctly; then confirms that *viewing* the older of the two
  remaining cached results moves it to most-recently-used, so a
  subsequent insert evicts the untouched one instead — proving the LRU
  behaviour, not just simple FIFO.
