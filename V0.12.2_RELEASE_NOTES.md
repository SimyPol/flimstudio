# FLIM Studio 0.12.2

## Bundled Leica `.lif` reader in the standalone exe

The packaged `FLIM Studio.exe` (0.12.1) could queue `.lif` files, but
actually scanning/exporting them still required a separately installed
**Leica Interrogator Desktop** folder with its own working Python `.venv`
pointed at from the sidebar. That's no longer required for the common
case: a build now ships its own core (no-GUI) copy of Interrogator's
`leica_flim_converter`, so scanning a `.lif` and exporting the datasets
you pick to `.ics` works right out of the box, same as native fitting
does.

An externally configured **Leica Interrogator Desktop** folder still
takes priority whenever one is set, and is still required for the
**Full GUI…** button (Interrogator's own full preview/export window) --
that stays a genuinely separate, separately-installed program, since it
depends on PySide6 and Interrogator's own GUI code, which this bundled
copy deliberately excludes.

### What's new

- [`flim_app/leica_bundled/`](flim_app/leica_bundled/) -- a vendored,
  manually-synced copy of `leica_flim_converter`'s core (scan + export,
  no GUI) plus its `LeicaFlimDecoder.dll` and two top-level dependencies.
  See its [`README_VENDORED.md`](flim_app/leica_bundled/README_VENDORED.md)
  for exactly what's included, why, and how to re-sync it later.
- `flim_app/_paths.py`: new `bundled_leica_root()`, mirroring the existing
  `app_root()` pattern, to locate that vendored copy in both source and
  frozen builds.
- `flim_app/leica_export_gui.py`: new `resolve_leica_backend()` picks
  between an externally configured Interrogator install and the bundled
  copy, and returns the right command line to run either one with.
  `WORKER_SCRIPT` now resolves via `app_root()` instead of
  `Path(__file__)`, which also fixes a latent bug: the *external*-install
  path was silently broken in 0.12.1's packaged exe, since `leica_worker.py`
  isn't a real file on disk once compiled into the app's own frozen
  archive -- it's now also shipped as a loose data file for exactly that
  reason (see `flim_studio.spec`).
- `run_flim_studio.py`: a new hidden `--leica-worker` flag, exactly
  mirroring `--native-worker`'s self-relaunch pattern -- a packaged exe's
  own bundled reader runs by relaunching itself as an isolated subprocess,
  rather than needing a standalone script file or a second interpreter.
- `flim_studio.spec`: bundles `flim_app/leica_bundled/` (walked
  file-by-file so the native DLL lands next to its Python wrapper the same
  way it does on disk) and ships `flim_app/leica_worker.py` itself as a
  loose file.
- `BUILDING.md` and the sidebar's Leica status text now describe the
  bundled reader; `README.md` and `USER_MANUAL.md` (and the `.docx`) no
  longer imply an Interrogator install is required for the quick `.lif`
  export path.

### Status

Implemented and reviewed via careful manual code tracing (no Python
interpreter available in this environment to run the build directly --
see `BUILDING.md`'s existing caveat). Please build via `build_exe.bat` and
confirm end to end: queuing a `.lif` with **no** "Leica Interrogator…"
folder configured should scan and export exactly as it did before when
one *was* configured.
