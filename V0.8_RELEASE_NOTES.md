# FLIM Studio 0.8 — corrected native mono-fit parity

Version 0.7 should not be used for quantitative FLIMLib reconvolution results
from the supplied IRF. Its release validation exercised the phasor path, while
the native path passed the IRF pedestal directly to FLIMLib and reused the ICS
acquisition interval as the native fitting interval.

Version 0.8 separates and records the two time intervals and prepares the IRF
prompt before native fitting:

- ICS acquisition interval: 0.390625 ns/bin.
- Saved LabVIEW native-fit interval: 0.4 ns/bin (editable).
- Native input: 29 leading bins (editable; -1 uses all acquisition bins).
- IRF pedestal: per-pixel temporal median subtraction followed by clipping to
  non-negative values (editable: median, tail median, or none).
- Mono-fit preset: Poisson fit weighting, fixed background 0, per-pixel IRF,
  minimum 1000 processed counts.
- Acquisition background remains corrected first using the independently
  verified sample/background ratio 20/800 = 0.025.

On the supplied sample/background/IRF triplet, this corrected path produced
170,836 successful/valid pixels, mean lifetime 3.260 ns, median 3.272 ns, and a
50-bin histogram maximum centred at approximately 3.32–3.36 ns. This closely
matches the supplied LabVIEW screen, whose distribution is centred near
3.4 ns. The remaining visual x/y orientation difference is not used to alter
pixel-to-IRF association because all three ICS acquisitions share one loader
and geometry; display orientation should be handled separately from fitting.
