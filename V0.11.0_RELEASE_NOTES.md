# FLIM Studio 0.11.0 (see also 0.11.1: shared IRF/background in the training dialog)

## Global lifetime model: Training mode and Application mode

Wires up the DLL's `flim_train_global_model_v1` / `flim_apply_global_model_v1`
entry points (already present in the bundled `flimfit_labview.dll` — no
rebuild needed). Two modes, as requested:

**Training mode** — a new **Train new model…** button in the sidebar's
**GLOBAL MODEL** section opens a dialog where you add several images, each
with its own IRF and optional background. Click **Train** and it finds one
shared set of lifetimes (mono/bi/tri, per the sidebar's Model order) across
every image in the set, using the sidebar's current native-fit settings
(Noise model, Background mode, IRF mode, Global iterations, Max pixels —
set those first). Once trained, **Save model…** writes it to a small JSON
file, and **Use this model now** switches the main window straight into
Application mode with it loaded.

**Application mode** — a new **FLIMLib — apply trained global model**
Lifetime method. Load a saved model with **Load model…** in the sidebar (or
train one and click "Use this model now"), pick any dataset the normal way
(including stepping through the existing file queue), and run analysis —
the shared taus are held fixed and only amplitude/background are fit per
pixel. Everything downstream (Multi-exponential tab, χ² map, decay curve,
phasor, exports) works exactly as it does for the other FLIMLib methods,
since apply-mode output is just a `NativeFitResult` like any other native
fit.

### How the two modes fit together

- A trained model is a JSON file (`flim_app/global_model.py`): the shared
  taus, plus the exact fitting conditions (bin width, background mode,
  noise model, IRF mode, fit window) they were trained under — so applying
  reproduces the same conditions rather than silently drifting. Also
  records provenance: which images, how many pixels were selected, when,
  under which DLL build.
- Applying a model overrides the sidebar's Model order / Noise model /
  Background mode / IRF mode / fit window with the model's own trained
  values for that run (spatial bin and timing offset stay under your
  control, since those are per-acquisition preprocessing, not part of what
  the taus mean). The sidebar hint text and Model order dropdown update to
  match whichever model is active.

### Known limitations of this first version

- Per-training-image preprocessing covers background subtraction, timing
  shift, and spatial binning — not yet detector-row/column interpolation or
  outlier smoothing. All training images must end up the same processed
  shape after binning.
- Training mode always builds an all-pixels mask and relies on the DLL's
  own minimum-photon threshold to exclude dim pixels (matching the
  documented `flim_train_global_model_v1` contract); there's no separate
  masking UI yet.
- Batch-apply across a whole folder in one action wasn't built this round
  (Application mode currently works one dataset at a time, as agreed) — say
  the word if you want that added.

## Files

- `flim_app/native_backend.py` — `GlobalTrainResult`, `train_global_model`/
  `apply_global_model` on `FLIMLibLabViewBackend`, `train_global_in_subprocess`/
  `apply_global_in_subprocess`, plus a refactor extracting the shared
  subprocess plumbing (`_run_native_subprocess`) so `fit_in_subprocess`
  keeps working unchanged.
- `flim_app/native_worker.py` — dispatches the two new modes.
- `flim_app/global_model.py` (new) — `TrainedGlobalModel`, save/load.
- `flim_app/processing.py` — `train_global_model()` orchestration,
  `flimlib_apply_global` integrated into `analyze_dataset()`.
- `flim_app/training_gui.py` (new) — the Training dialog.
- `flim_app/gui.py` — Global model sidebar section, new Lifetime method.
- `flim_app/models.py` — `AnalysisSettings.global_model_path`.

## Verification

- `tests/test_global_model.py` (new): trains a shared bi-exponential model
  across two synthetic images via the real DLL, checks the output taus are
  sorted longest-to-shortest like everywhere else in the app; and a second
  test does a full save → load → apply round trip against an unseen third
  dataset, confirming the applied per-pixel tau maps exactly equal the
  trained fixed values wherever the fit succeeded.
