# FLIM Studio 0.12.5

## Native bin width now tracks Time-bin width automatically

A real footgun: **Native bin width (ns)** (NATIVE FLIMLIB FIT) was a
plain, independent text field defaulting to `0.4` (the original LabVIEW
VI fixture's value), with nothing keeping it in sync with **Time-bin
width** (TIMING & METHOD). Since `bin_width_ns` is passed straight to
`flim_fit_pixels_v2`/`flim_fit_global_pixels_v2` to convert a bin index to
real time, any mismatch between the two silently scales every
reconvolution/global-fit lifetime by `native_bin_width_ns / dt_ns` — the
bundled demo dataset itself was already affected (dt_ns 0.390625 vs. the
hardcoded 0.4 default).

New sidebar control: **Native bin width mode**, `Auto` (new default) /
`Manual`. In `Auto`, the native fit always uses whatever **Time-bin
width** currently is — updating live if it changes — and the manual entry
field below it is ignored entirely. `Manual` uses that field's value
instead, for the narrow case of deliberately testing/reproducing a fixed
historical bin width (e.g. the original VI's `0.4`) that's different from
the loaded data's own. A summary line always reports which is in effect
and the resolved number.

### What's new

- `flim_app/gui.py`: new `native_bin_width_mode_var` (Auto/Manual combo)
  and `native_bin_width_summary_var`; new `_native_bin_width_mode_changed()`
  keeps the summary truthful, wired via traces on the mode, the manual
  entry, and `dt_var` itself — the mechanism that makes Auto mode actually
  *track* Time-bin width live, not just default-match it once.
  `_settings()` now sends `-1.0` (the existing "auto" sentinel — see
  below) in Auto mode regardless of the manual field's contents, or that
  field's value in Manual mode. `_activate_trained_model` sets the mode to
  `Manual` when mirroring a trained model's fixed bin width, since that's
  a baked-in training condition, not something that should look like it's
  still tracking the current dataset.
- No `AnalysisSettings`/`models.py` schema change needed: `native_bin_width_ns
  <= 0` already meant "auto → use dt_ns" in `normalized()` before this —
  the GUI just never actually produced that sentinel by default, and had
  no way to toggle back to it once a manual number was in the field. This
  also means the 0.12.3 settings-preset `.ini` save/load already round-trips
  the new mode correctly with no extra code: Auto and Manual are just
  `<=0` vs. a real number in the one existing field.
- `flim_app/models.py`: doc-comment only, clarifying the existing `<=0`
  sentinel's relationship to the new UI mode.
